<objective>
Run a manual end-to-end smoke test of the Phase 2 streaming endpoint against the running `npx next dev` server and a real Supabase auth session, then record the results in `02-UAT.md`. This plan exists because:

1. The streaming round-trip (real OpenRouter call → real SSE pipe → real client consumption) cannot be unit-tested in Vitest without mocking away the entire purpose of the route.
2. Phase 2 success criteria #1 ("le premier token arrive en moins de 1 seconde") and #4 ("Je n'ai pas d'exemple pertinent") and #6 (loi Hoguet refusal) are LLM-side behaviors that require an actual model call.
3. Plan 01-05's checkpoint pattern (Playwright-driven verification against the dev server) proved this works: see `.planning/phases/01-context-layer-data-hygiene/01-05-SUMMARY.md` for the orchestrator-driven flow.

This is NOT a unit-test plan. It is a checkpoint plan: the executor starts the dev server, authenticates, runs 7 documented curl/Playwright sequences, captures evidence (status codes, timings, SSE body excerpts, server logs), and writes a single UAT.md report.

Output: `02-UAT.md` with status (pass/fail/diagnosed) per criterion and reproducible curl commands.
</objective>

Endpoint under test: `POST http://127.0.0.1:3000/api/copilot/stream`
Demo header: `X-Demo-Mode: true`

Required env (must be present in .env.local for non-demo path):
- OPENROUTER_API_KEY
- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_ANON_KEY
- SUPABASE_SERVICE_ROLE_KEY
- COACH_RAG_DEFAULT_MODEL (optional — defaults to anthropic/claude-sonnet-4-5)

Authentication: per plan 01-05, the `/demo` page provides client-side Zustand auth which DOES NOT create a Supabase server-side session. The streaming route uses `requireAuth()` which DOES require a server-side Supabase session. Therefore:

- For the **demo-mode short-circuit** test (UC-1, UC-2): the route returns 401 BEFORE checking the X-Demo-Mode header in the current implementation. We must therefore either (a) authenticate as a real user against Supabase first, OR (b) accept that demo-mode is testable only as a unit test (already covered in plan 02-02 test "demo short-circuit").

  Resolution: re-check route order in plan 02-02 — `requireAuth()` runs FIRST, then `checkRateLimit`, then demo header. The demo header path REQUIRES auth (X-Demo-Mode is a hint from an already-authenticated client, not a bypass). This is consistent with the suggested_plan_structure in 02-CONTEXT.md ("Client signals demo mode via header `X-Demo-Mode: true` (set in Phase 4 wiring). Server treats it as authoritative — no LLM call"). The intent: demo USERS are still authenticated (e.g., a "demo agency" account); the header just tells the server not to bill the LLM.

  So the UAT requires a real Supabase login. Use the existing register/login pages.

Acquisition of an authenticated cookie for curl:
```bash
# Option A: Playwright (recommended — mirrors plan 01-05's pattern)
# Option B: log in via browser, copy the sb-* cookies, paste into curl -H "Cookie: sb-*=..."
```

Reference curl skeleton (non-demo):
```bash
curl -N -X POST http://127.0.0.1:3000/api/copilot/stream \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-<project>-auth-token=<value>" \
  -d '{"messages":[{"role":"user","content":"Comment je signe plus de mandats exclusifs ?"}],"context":null}'
```

Reference curl skeleton (demo):
```bash
curl -N -X POST http://127.0.0.1:3000/api/copilot/stream \
  -H "Content-Type: application/json" \
  -H "X-Demo-Mode: true" \
  -H "Cookie: sb-<project>-auth-token=<value>" \
  -d '{"messages":[{"role":"user","content":"hi"}]}'
```

The `-N` flag disables curl buffering — essential for observing SSE events as they arrive.

    Expected: first 10 return 200, 11th returns 429. Pass if 11th is 429.
